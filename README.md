# Refactoring evidence
I reduced duplication by creating a single rule for all of the cards on my resume page and all of the figures on my work page. I replaced repeated values such as color font-family, and spacing sizes with variables. I clarified naming by giving my color variables names that represent what parts of the website I am styling with them. For example, my green color is mostly used for cards and the nav buttons as well as the hero background, so I named it --hero-card-nav. Before my refactoring, I had four separate card names for each card on my resume page. After refactoring, I named all four cards ".card" instead. This allowed me to write one ruleset for all four cards, instead of one individual ruleset.

# Architecture notes
I chose to use the most common layer order strategy: base, layout, components, utilities, overrides, and print. I chose this order because it goes from broad to more specific, and also follows a simple organizational pattern. I chose tokens that are likely to be reused again and again throughout the design process, such as one consistent border-radius, and all of my colors. I also created some tokens for my fonts so that I do not have to remember the specific sizes intended for each layer of text. My naming approach was based in what currently makes sense for me. I named everything what it is. For example, the figures on the work page, are housed in a class called work-grid, and the cards on the resume page are housed in a class called card-grid. I may need to generate more specific names if I add more elements to my pages. I named my colors after what components they primarily style. I used my browser checks to make sure that each CSS rule applied correctly. I viewed my website in Firefox and Chrome at 450px, 750px, and 1080px. I also used validation tools to make sure that there were no syntax or semantic issues. In addition, I checked my focus order both manually and in Silktide, to make sure that the buttons tabbed correctly. My manual check was to make sure that the outlines appeared around the buttons, as I had created a command for, and my Silktide check was to make sure that the computer was reading the focus order correctly.
